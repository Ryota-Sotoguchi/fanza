# FANZA セール自動投稿ツール(X向け・Windows 11)

DMMアフィリエイトAPIで FANZA動画のセール商品を取得し、Anthropic API で短い紹介文を作って、決まった時間帯に X へ投稿するツールです。

---

## はじめに: selfcheck とドライラン

[セットアップ](#セットアップ)が終わったら、本番の前に必ずこの2つを実行してください。どちらも**投稿はしません**。

### 1. selfcheck(設定・API・ログイン状態の確認)

```bat
scripts\selfcheck.bat
```

次の項目を順に確認し、`[OK]` / `[NG]` で表示します。

| 項目 | 確認する内容 |
|---|---|
| 設定ファイル | `config.yaml` を読み込めるか(書き間違いがあれば、どの項目かを表示) |
| 運用フェーズ | 今日が「開始前 / 慣らし運用 何日目 / 自動投稿 何週目」のどれか、今日の予定件数 |
| 収集対象 | 対象フロア(初期値は `videoa` のみ)と割引率の下限 |
| .env | `DMM_API_ID` / `DMM_AFFILIATE_ID` / `ANTHROPIC_API_KEY` が入っているか |
| 計測用アフィリエイトID | トーン・まとめ形式ごとのIDが正しく組み立てられるか(例: `TA=yourname-991`) |
| データベース | `data/fanza.db` に書き込めるか |
| DMMアフィリエイトAPI | 各フロアに1件だけ問い合わせて応答があるか |
| Anthropic API | APIキーと `generation.model` のモデル名が有効か(文章は生成しないので料金はかかりません) |
| Xのログイン状態 | 保存したブラウザプロファイルでログインできているか、警告・本人確認などの画面が出ていないか |
| 停止状態 | 安全装置で停止していないか |

結果の例:

```
=== selfcheck 結果 ===
[OK] 設定ファイル: C:\fanza\config.yaml
[OK] 運用フェーズ: 本日(2026-10-06): 慣らし運用(ドライラン) 1日目 / 予定 6 件 / 自動投稿の開始日 2026-10-20
[OK] 収集対象: フロア videoa / 割引率 50% 以上
[OK] .env: OK
[OK] 計測用アフィリエイトID: TA=yourname-991 / TB=yourname-992 / TC=yourname-993 / SA=yourname-994 / SB=yourname-995
[OK] データベース: C:\fanza\data\fanza.db
[OK] DMMアフィリエイトAPI: videoa: 応答あり(1件)
[OK] Anthropic API: モデル claude-haiku-4-5(Claude Haiku 4.5)
[OK] Xのログイン状態: @youraccount でログイン中(投稿はしていません)
[OK] 停止状態: 停止していません

すべて OK です。
```

オプション:

- `scripts\selfcheck.bat --notify-test`: Windows通知のテストも行う(停止時の通知が届くか確認できます)
- `scripts\selfcheck.bat --skip-browser`: ブラウザを開かずに確認する
- `scripts\selfcheck.bat --skip-api`: DMM / Anthropic API への問い合わせを省く

よくある NG と対処:

| NG の内容 | 対処 |
|---|---|
| `.env: 未設定: ...` | `.env` に値を入れる([セットアップ](#セットアップ)の手順2) |
| `DMM_AFFILIATE_ID は末尾が990〜999の…` | APIで使えるのは末尾990〜999のIDだけです。`yourname-990` の形にする |
| `Xのログイン状態: ログイン切れ` | `scripts\login.bat` でログインし直す |
| `Xのログイン状態: ブラウザを起動できません` | Edge が起動中のプロファイルと競合していないか確認。`config.yaml` の `post.browser_channel` を見直す |
| `停止状態: 停止中` | [停止したときの対応](#停止したときの対応) を参照 |

### 2. ドライラン(投稿せずに文面だけ確認)

```bat
scripts\dryrun.bat
```

1. DMMアフィリエイトAPIからセール商品を取得します(割引率50%以上・除外リストに当たらないもの)。
2. ジャンルが偏らないように選んだ3件について、トーン TA/TB/TC で紹介文を1件ずつ生成します。
3. 割引率TOP5のまとめ投稿を1件作ります。
4. 画面に表示し、`output\dryrun\sample_日付_時刻.txt` に保存します。

出力の例:

```
------------------------------------------------------------
[1/4] 予定 13:20  個別  パターン TA-H12-SGL
(トーン: 事実簡潔 / ジャンル: 単体 / アフィリエイトID: yourname-991)
商品ID: abc00123
画像: https://pics.dmm.co.jp/digital/video/abc00123/abc00123pl.jpg

▼本文
(生成された100字前後の紹介文)
#PR

▼リプライ(本文を投稿したあと、自分の投稿に返信する)
https://al.dmm.co.jp/?lurl=...&af_id=yourname-991&ch=api
#PR
```

確認するポイント:

- 本文に露骨な表現や、データにない数字(評価・売上など)が入っていないか
- 本文の末尾が `#PR` になっていて、本文に URL が入っていないか
- リプライのURLの `af_id=` が、トーンごとの計測用ID(991〜995)になっているか
- 除外したい作品が混ざっていないか(除外した作品は `logs\excluded\日付.csv` に理由付きで記録されます)

オプション:

- `--count 5`: 個別投稿のサンプル数を変える
- `--no-collect`: APIから取得し直さず、保存済みの候補を使う
- `--weekly`: まとめ投稿を週間TOP5で作る

ドライランのサンプルは、投稿の予定や商品の状態(待機/投稿済みなど)を変えません(取得した商品情報の保存・更新だけ行います)。

**ドライランの3つの形:**

| 形 | 動き |
|---|---|
| `scripts\dryrun.bat` | 上記のサンプル出力。いつでも何度でも実行できる |
| 慣らし運用(開始から14日間) | 自動でドライランになり、その日の全件の下書きを `output\manual\日付.txt` に出力(手動投稿用) |
| `config.yaml` の `dry_run: true` | 15日目以降も投稿せず、慣らし運用と同じく下書きを出力し続ける |

## 重要な注意

- **Xの規約について**: Xの自動化ルールでは、API以外の方法(Webサイトのスクリプト操作)による自動化は認められていません。このツールは Playwright でブラウザを操作して投稿するため、安全装置を入れていてもアカウント凍結のリスクがあります。投稿処理は `src/fanza_poster/post/base.py` のインターフェースに分けてあり、X API による投稿へ差し替えられる作りにしています。
- **センシティブ設定**: パッケージ画像を添付するので、X の「設定とプライバシー → プライバシーと安全 → ポストするコンテンツ → ポストするメディアをセンシティブな内容を含むものとして設定する」をオンにしてください。
- **広告表記**: 本文の末尾に必ず `#PR` を付けます(システムで付与し、外せないようになっています)。リンクのリプライにも初期設定で `#PR` を付けています。
- **DMMアフィリエイトの規約**: SNSでの紹介や画像の扱いは、DMMアフィリエイトの規約に従ってください。添付する画像はAPIが返したパッケージ画像だけです。
- **実装していない操作**: 自動のいいね、フォロー、引用、他人へのリプライは実装していません。リプライは自分の投稿に対してだけ行い、他人の投稿のURLが渡された場合は拒否します。

## セットアップ

前提: Windows 11、Python 3.11 以上(3.12 推奨。[python.org](https://www.python.org/downloads/windows/) からインストールし、「Add python.exe to PATH」にチェック)、Microsoft Edge(標準搭載)。

1. **依存関係のインストール**: このフォルダで `scripts\setup.bat` を実行します。`.venv` が作られ、必要なパッケージが入ります。
2. **`.env` の設定**: `setup.bat` が `.env.example` から `.env` を作るので、メモ帳で開いて値を入れます。
   ```
   DMM_API_ID=(DMMアフィリエイトのAPI ID)
   DMM_AFFILIATE_ID=yourname-990   ← 収集用。末尾990〜999のAPI用ID
   ANTHROPIC_API_KEY=sk-ant-...
   ```
3. **`config.yaml` の確認**: 最低限、`start_date`(慣らし運用の開始日)を設定します。そのほかの項目は [config.yaml の主な項目](#configyaml-の主な項目) を参照してください。
4. **X へのログイン**: `scripts\login.bat` を実行するとブラウザ(Edge)が開くので、**ご自身で** ID・パスワード・確認コードを入力してログインします。終わったらコマンドの画面で Enter を押します。ログイン状態は `profile\` フォルダに保存され、以降の投稿で使われます。
   - 表示されたアカウント名を `config.yaml` の `post.x_handle` に入れておくと、別アカウントでの誤投稿を防げます。
   - ツールがログイン操作を自動で行うことはありません。
5. **確認**: [selfcheck](#1-selfcheck設定apiログイン状態の確認) と [ドライラン](#2-ドライラン投稿せずに文面だけ確認) を実行します。
6. **タスクスケジューラへの登録**: 次の章の手順で登録します。

## タスクスケジューラの設定(スリープ解除あり)

`scripts\tick.bat` を **11:50 から翌1:50 まで10分おき**に実行します。1回の実行で行うことは次のとおりです。

- その日の最初の実行: セール商品の収集 → その日の投稿計画(件数・時刻・パターン・文面)の作成
- 毎回: 予定時刻を過ぎた投稿を**1件だけ**処理する(スリープ復帰直後にまとめて投稿しないため)。予定時刻から60分以上遅れた枠は投稿せずスキップします。

### 方法A: スクリプトで登録(おすすめ)

PowerShell をこのフォルダで開き、次を実行します(管理者権限は不要です)。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\register_tasks.ps1
```

「タスクを実行するためにスリープを解除する」(WakeToRun)が有効なタスク `FanzaPoster_Tick` が登録されます。削除するときは `-Unregister` を付けて実行します。

### 方法B: 手動で登録

1. スタートメニューで「タスク スケジューラ」を開き、右側の **「タスクの作成...」** をクリックします(「基本タスクの作成」ではありません)。
2. **全般** タブ
   - 名前: `FanzaPoster_Tick`
   - **「ユーザーがログオンしているときのみ実行する」** を選びます(投稿時にブラウザの画面を開くため)。
3. **トリガー** タブ → 「新規」
   - 「毎日」、開始時刻 `11:50`
   - 詳細設定の **「繰り返し間隔」** にチェックして `10 分間`、**「継続時間」** に `14 時間` を直接入力します(一覧にない値も入力できます)。
   - 「有効」にチェックして OK。
4. **操作** タブ → 「新規」
   - 操作: 「プログラムの開始」
   - プログラム/スクリプト: `C:\(このフォルダ)\scripts\tick.bat`
   - 開始(オプション): `C:\(このフォルダ)`
5. **条件** タブ
   - **「タスクを実行するためにスリープを解除する」にチェック**(ご依頼の「スリープを解除してタスクを実行する」設定はこの項目です)
   - ノートPCの場合は「コンピューターをAC電源で使用している場合のみタスクを開始する」のチェックを外します。
6. **設定** タブ
   - 「スケジュールされた時刻にタスクを開始できなかった場合、すぐにタスクを実行する」にチェック
   - 「タスクを停止するまでの時間」: `30 分間`
   - 「タスクが既に実行中の場合に適用される規則」: **「新しいインスタンスを開始しない」**
7. OK で保存します。

### 電源オプション(スリープ解除タイマーを許可する)

タスク側で「スリープを解除する」にしても、Windows の電源設定でスリープ解除タイマーが無効だと起動しません。

1. コントロールパネル → ハードウェアとサウンド → 電源オプション → 使用中のプランの「プラン設定の変更」
2. 「詳細な電源設定の変更」→ **「スリープ」→「スリープ解除タイマーの許可」→「有効」**(ノートPCは「バッテリ駆動」「電源に接続」の両方)
3. OK で保存します。

注意:

- **サインアウトやシャットダウンをすると動きません**(スリープと画面ロックは問題ありません)。
- 休止状態からの復帰は機種によってはできません。スリープを使ってください。
- 動作は `logs\日付.log` と `scripts\fp.bat status` で確認できます。

## 運用の流れ

```
開始日(start_date)
 ├ 1〜14日目   慣らし運用: 自動投稿しない。毎日の下書きを output\manual\日付.txt に出力(手動投稿用)
 ├ 15日目〜    自動投稿 1週目: 1日6件
 ├ 22日目〜    2週目: 1日8件
 └ 29日目〜    3週目以降: 1日12件
```

- **件数**: 1日の件数はまとめ投稿を含みます。`schedule.weekly_posts` で変更でき、`schedule.daily_hard_limit`(初期値12)を超えることはありません。
- **時刻**: 12:00〜翌1:00 の間でランダムに決めます。21時以降は1時間あたりの件数が多くなるように重み付けし、投稿同士は30分以上あけます。
- **まとめ投稿**: 1日1件、その日に取得したセール商品の割引率TOP5を投稿します(21:00〜23:00 の間)。日曜日は直近7日間の週間TOP5にします。作品名は露骨な語を含むことが多いため、作品ごとに生成AIで作った短いラベル(検証済み)を使います。
- **候補の選び方**: 割引率の高い順に、ジャンル(VR/単体/シリーズ/その他)とトーンが偏らないように割り当てます。同じ商品を2回個別投稿することはありません。
- **投稿直前の確認**: 投稿の直前にAPIで価格を取り直し、セールが終わっていれば別の商品に差し替えます。価格が変わっていれば紹介文を作り直します。
- **慣らし期間中に下書きに出した商品**は「手動用出力済み」として、本番開始後の自動投稿には使いません。

### パターンID

投稿ごとに、文面のトーン・時間帯・ジャンル・まとめ形式を表すパターンIDを記録します。

| 種類 | 形式 | 例 |
|---|---|---|
| 個別投稿 | `トーン-時間帯-ジャンル` | `TB-H21-VR` |
| まとめ投稿 | `形式-時間帯-期間(D=日次/W=週間)` | `SA-H21-W` |

| 区分 | コード |
|---|---|
| トーン | TA 事実簡潔 / TB お得感 / TC 作品紹介 |
| 時間帯 | H12 12〜15時 / H15 15〜18時 / H18 18〜21時 / H21 21〜翌1時 |
| ジャンル | VR / SGL 単体 / SER シリーズ / OTH その他 |
| まとめ形式 | SA ランキング形式 / SB 価格一覧形式 |

## 安全装置

| 安全装置 | 動き |
|---|---|
| ログイン切れ・CAPTCHA・本人確認・ロック・凍結の検知 | 突破を試みず、その場で全処理を停止。ログに記録し、画面を `logs\screenshots\` に保存し、Windowsの通知を出す |
| 警告・制限の検知(自動化・スパムの警告、投稿数の上限など) | 上記の停止に加えて、**件数の引き上げを止める**(再開後もその時点の件数で据え置き) |
| 連続失敗 | 3回連続で投稿に失敗したら停止(`safety.max_consecutive_failures`) |
| 1日の上限 | `schedule.daily_hard_limit` を超えて投稿しない(まとめ投稿を含めて数える。リンクのリプライは数えない) |
| 多重起動の防止 | タスクと手動実行が重なったら、後から起動したほうは何もしない |
| 文面の検証 | NG語・除外キーワード、データにない数字、割引率・価格の不一致、URL・ハッシュタグ・絵文字、文字数を確認。不合格なら理由を伝えて再生成し、それでもだめならその商品をスキップ |
| ドライランモード | `config.yaml` の `dry_run: true`、または `scripts\fp.bat tick --dry-run` |

### 停止したときの対応

1. 通知、または `data\HALTED.txt` で停止理由を確認します。
2. ブラウザで X を開き、警告・本人確認などを**ご自身で**確認・解消します。
3. `scripts\fp.bat resume` で再開します(確認の質問に `y`)。
4. 警告・制限で停止した場合、件数は据え置きのままです。引き上げを再開してよいと判断したら `scripts\fp.bat unfreeze-ramp` を実行します。

撤退基準では、警告・制限を検知したら即停止としています。再開するかどうかは慎重に判断してください。

## 計測と撤退

### トーンごとのアフィリエイトID

文面スタイルごとに別のアフィリエイトIDをリンクに使い、DMMのレポートでIDごとのクリック数を見て比較します。対応は `config.yaml` の `tracking.affiliate_ids` で変えられます。

| スタイル | 初期値のID |
|---|---|
| TA 事実簡潔 | `yourname-991` |
| TB お得感 | `yourname-992` |
| TC 作品紹介 | `yourname-993` |
| SA まとめ(ランキング形式) | `yourname-994` |
| SB まとめ(価格一覧形式) | `yourname-995` |
| 収集用(.env) | `yourname-990`(クリックは発生しません) |

番号だけを書くと、`.env` の `DMM_AFFILIATE_ID` の末尾を置き換えて使います。`"yourname-996"` のように完全なIDで書くこともできます。

### 投稿の記録

投稿ごとに `data\posts_log.csv` に1行追記します(Excelで開けます)。

列: 記録時刻 / 運用日 / 予定時刻 / 種別 / 商品ID / ジャンル / パターンID / スタイル / 時間帯 / アフィリエイトID / 投稿文 / リプライ文 / 結果 / 投稿URL / エラー / ドライラン

### クリック数の入力(手入力)

DMMアフィリエイトのレポートを見て、次のCSVに入力します。最初に `scripts\weekly_report.bat` を実行すると、見出しだけのファイルが作られます。Excelで編集して、CSV(UTF-8 または Shift_JIS)で保存してください。

**`data\clicks_by_id.csv`(必須)**: アフィリエイトIDごとのクリック数

```csv
日付,アフィリエイトID,クリック数,成果数
2026-10-20,yourname-991,12,0
2026-10-20,yourname-992,8,1
2026-10-20,yourname-994,20,0
```

1日ごとでも、週の合計を週内のどこか1日の日付で入力してもかまいません。

**`data\clicks_by_item.csv`(任意)**: 商品ごとのクリック数。DMMのレポートで商品別のクリック数が分かる場合だけ入力します。入力すると、ジャンル別・時間帯別の比較もできるようになります。

```csv
日付,商品ID,クリック数,成果数
2026-10-20,abc00123,5,0
```

### 週次集計

```bat
scripts\weekly_report.bat            (直近で終わった週)
scripts\weekly_report.bat --week 3   (週を指定)
```

`reports\week_NN.md`(読みやすい形)と `reports\week_NN.csv` を出力します。内容は次のとおりです。

- 文面スタイル別(アフィリエイトID別): 投稿数・クリック数・成果数・**1投稿あたりクリック数**・成約率
- ジャンル別・時間帯別・パターンID別(商品別データがある場合のみ)
- 週次推移(全体の1投稿あたりクリック数)
- 撤退判定
- 無効化候補

表示回数(インプレッション)は取得しないため、「クリック率」は **1投稿あたりのクリック数(クリック数 ÷ リンク付きで投稿できた件数)** で表しています。

### 下位パターンの無効化(手動承認制)

```bat
scripts\review.bat
```

直近2週間(`analytics.review_weeks`)で投稿数が10件以上あるパターンのうち、1投稿あたりクリック数が同じ区分の平均の80%未満で最も低いものを候補として表示します。`y` と答えたものだけを無効化し、それ以降の計画で使わなくなります。何も答えなければ変更しません。

- 現在の状態の確認: `scripts\fp.bat review --list`
- 元に戻す: `scripts\fp.bat review --enable tone TB`(区分は `tone` / `band` / `genre` / `summary_format`)
- 各区分で最低1つは有効のまま残ります。

### 撤退基準

- **警告・制限を検知したら即停止**(自動。[安全装置](#安全装置)を参照)。
- それ以外は8週間続け、**第8週の集計**で、第1〜8週の「1投稿あたりクリック数」の傾き(最小二乗法)が0以下、つまり上昇傾向でなければ、レポートに **「停止を提案」** と表示します。自動では止めません。
- 判定する週と基準は `analytics.exit_week` と `analytics.exit_min_slope` で変えられます。

## トラブルシューティング

- **投稿されない**: `scripts\fp.bat status` で今日の計画と結果を確認します。「開始前」「慣らし運用」なら投稿しないのが正しい動きです。`logs\日付.log` も確認してください。
- **「候補不足」になる**: 割引率の下限が高い、除外キーワードが広い、などが原因です。`logs\excluded\日付.csv` で除外理由を確認し、必要なら `config.yaml` を調整します。
- **画面の構成が変わって投稿に失敗する**: X の画面変更で要素が見つからなくなることがあります。失敗時の画面が `logs\screenshots\` に保存されます。3回続けて失敗すると停止します。
- **時刻がずれる**: PCの時刻設定とタイムゾーン(東京)を確認してください。
